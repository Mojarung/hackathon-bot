# Google Календарь: подключение

Бот умеет писать таймлайны хакатонов в **один** ваш Google Календарь. Не по
календарю на хакатон — один общий, поэтому в названии каждого события видно, к
какому хакатону оно относится: `🏁 Сдача проекта · ЛЦТ 26`.

Владелец календаря — вы, а не бот. Бот получает право «вносить изменения в
мероприятия» и ничего больше: календарь он не создаёт и удалить его не может.
Дальше этот календарь шарится команде обычным гугловым способом.

Интеграция **выключена по умолчанию**. Пока `GOOGLE_CALENDAR_ID` пуст, бот
работает ровно как раньше и в Google не ходит вообще.

Вся настройка — примерно 10 минут и делится на три части: ключ в Google Cloud,
календарь в Google Календаре, две строчки в `.env`.

---

## Часть 1. Сервис-аккаунт и ключ

Сервис-аккаунт — это «робот-пользователь» Google со своим e-mail. Пароля у него
нет, вместо пароля — JSON-файл с приватным ключом.

### 1.1. Создать проект

1. Откройте [console.cloud.google.com](https://console.cloud.google.com/).
2. Вверху слева, рядом с логотипом Google Cloud, — выпадающий список проектов.
   Нажмите на него → **New project** / **Создать проект**.
3. Название любое, например `hackbot`. Organization можно оставить как есть.
   **Create**.
4. Дождитесь уведомления о создании и **переключитесь на новый проект** в том же
   выпадающем списке. Это легко забыть, а дальше всё делается внутри проекта.

### 1.2. Включить Google Calendar API

Свежий проект не умеет ничего: каждое API включается отдельно.

1. Меню слева (☰) → **APIs & Services** → **Library** («Библиотека»).
2. В поиске наберите `Google Calendar API`, откройте его.
3. Нажмите **Enable** / **Включить**.

### 1.3. Создать сервис-аккаунт

1. **APIs & Services** → **Credentials** («Учётные данные»).
2. Вверху **+ Create credentials** → **Service account**.
3. **Service account name**: например `hackbot`. Поле **Service account ID**
   заполнится само — из него получится e-mail вида
   `hackbot@ваш-проект.iam.gserviceaccount.com`. Этот адрес понадобится в части 2,
   можно сразу скопировать.
4. **Create and continue**.
5. Шаги «Grant this service account access to project» и «Grant users access» —
   **пропустите**, нажмите **Done**. Роли в проекте здесь не нужны: доступ к
   календарю выдаётся не тут, а в самом Google Календаре.

### 1.4. Скачать JSON-ключ

1. В списке **Service accounts** нажмите на только что созданный аккаунт.
2. Вкладка **Keys** → **Add key** → **Create new key**.
3. Тип — **JSON**. **Create**.
4. Файл скачается сам, один раз. Второй раз его скачать нельзя — только выпустить
   новый ключ.

### 1.5. Положить ключ на сервер

```bash
scp ~/Downloads/ваш-проект-1a2b3c4d.json user@сервер:/путь/к/hackathon-bot/data/google-service-account.json
chmod 600 /путь/к/hackathon-bot/data/google-service-account.json
```

> **Ключ не должен попасть в git.** `data/` целиком лежит в `.gitignore` — именно
> поэтому файл кладётся туда, а не в корень проекта. Не переименовывайте его в
> что-то вне `data/`, не вставляйте содержимое в чат и не коммитьте.

Если положили в другое место — укажите путь в `GOOGLE_CREDENTIALS_FILE`.
Относительный путь считается от корня проекта.

## Часть 2. Календарь и доступ

### 2.1. Создать календарь

1. Откройте [calendar.google.com](https://calendar.google.com/).
2. Слева, в блоке **«Другие календари»** — значок **+** → **«Создать календарь»**.
3. Название — например `Хакатоны`. Часовой пояс на ваше усмотрение: бот всё равно
   отправляет каждое событие с часовым поясом его хакатона.
4. **«Создать календарь»**. Через пару секунд он появится в списке слева.

### 2.2. Дать доступ сервис-аккаунту

1. Наведите курсор на новый календарь в списке слева → три точки → **«Настройки и
   доступ»**.
2. Раздел **«Предоставление доступа отдельным пользователям или группам»** →
   **«+ Добавить пользователей и группы»**.
3. Вставьте e-mail сервис-аккаунта — `hackbot@ваш-проект.iam.gserviceaccount.com`
   (тот самый, из шага 1.3).
4. **Разрешения** — выберите **«Внесение изменений в мероприятия»**.
5. **«Отправить»**. Никакого письма-приглашения ждать не нужно: у робота нет
   почтового ящика, доступ выдаётся сразу.

> ⚠️ **Самая частая ошибка.** В списке прав есть похожий пункт **«Просмотр всех
> мероприятий»** — его недостаточно, бот получит 403 на каждой записи. Нужен
> именно **«Внесение изменений в мероприятия»**. Права «Внесение изменений и
> управление доступом» тоже сработают, но это больше, чем боту нужно.
>
> Проверить себя можно там же: напротив адреса сервис-аккаунта должно быть
> написано «Внесение изменений в мероприятия».

### 2.3. Скопировать идентификатор календаря

На той же странице настроек прокрутите ниже до раздела **«Интеграция
календаря»**. Первое поле — **«Идентификатор календаря»**, выглядит примерно так:

```
c_a1b2c3d4e5f6g7h8@group.calendar.google.com
```

Скопируйте его целиком, вместе с `@group.calendar.google.com`.

> Не перепутайте с полем **«Публичный адрес в формате iCal»** — это другое.
> И не подставляйте сюда свой личный адрес почты: личный календарь сервис-аккаунту
> расшарить с нужными правами не выйдет.

## Часть 3. `.env` и запуск

```env
GOOGLE_CALENDAR_ID=c_a1b2c3d4e5f6g7h8@group.calendar.google.com
GOOGLE_CREDENTIALS_FILE=data/google-service-account.json
GOOGLE_CALENDAR_SYNC_MINUTES=30
```

Перезапустите бота:

```bash
sudo systemctl restart hackbot
journalctl -u hackbot -f
```

Первая полная сверка зальёт в календарь события всех живых хакатонов. Дальше
правки таймлайна уезжают в календарь сами, а раз в `GOOGLE_CALENDAR_SYNC_MINUTES`
минут бот делает полный проход и убирает из календаря то, что удалили в боте.

## Часть 4. Поделиться календарём с командой

Календарь ваш, поэтому шарится он как любой другой:

- **Всем поимённо:** «Настройки и доступ» → «Предоставление доступа отдельным
  пользователям» → добавить участников с правами **«Просмотр всех мероприятий»**.
  Права на изменение им не нужны — пишет туда бот.
- **Ссылкой:** там же, «Разрешения на доступ» → **«Сделать общедоступным»**, затем
  в разделе «Интеграция календаря» взять **«Общедоступный URL для этого
  календаря»**. Кто угодно со ссылкой увидит расписание.
- **Подписка в чужой Google-аккаунт:** дать человеку «Идентификатор календаря», он
  добавляет его через «Другие календари» → **«+»** → **«Подписаться на
  календарь»**.
- **Apple Calendar / Outlook:** «Интеграция календаря» → **«Секретный адрес в
  формате iCal»**. Секретный — значит, ссылка равна доступу; в открытый чат её
  выкладывать не стоит.

У бота, к слову, есть и свои `.ics`-ленты (`/ics` и `/ics/<slug>.ics`) — они
работают независимо от Google и никакой настройки не требуют.

## Если не работает

Смотрите логи: `journalctl -u hackbot -f`. Ошибки Google приходят с кодом.

### Ничего не происходит, в логах тишина

Интеграция просто выключена. Она включается, только если **оба** условия верны:
`GOOGLE_CALENDAR_ID` не пуст **и** файл по пути `GOOGLE_CREDENTIALS_FILE`
существует. Проверьте:

```bash
ls -l data/google-service-account.json
grep GOOGLE_ .env
```

Частая причина — путь. Относительный путь считается от корня проекта, а не от
того каталога, откуда вы запустили команду.

### 403 — доступа нет

Календарь не расшарен сервис-аккаунту, или ему дали только **«Просмотр всех
мероприятий»**. Вернитесь к шагу 2.2 и убедитесь, что стоит **«Внесение изменений
в мероприятия»**.

Второй вариант той же ошибки: e-mail скопировали с опечаткой или взяли адрес
другого сервис-аккаунта. Нужный адрес — поле `client_email` внутри JSON-файла:

```bash
uv run python -c "import json;print(json.load(open('data/google-service-account.json'))['client_email'])"
```

Третий вариант, если 403 говорит про `accessNotConfigured`: в проекте не включён
Google Calendar API — шаг 1.2.

### 404 — календарь не найден

Неверный `GOOGLE_CALENDAR_ID`. Проверьте, что скопировали именно **«Идентификатор
календаря»** из раздела «Интеграция календаря», целиком и без пробелов по краям,
и что это тот календарь, который вы расшарили.

Ещё вариант: календарь удалён, или идентификатор взят от календаря в другом
Google-аккаунте.

### 401 — ключ не принят

JSON-ключ битый, обрезан или не тот. Проверьте, что файл валиден и содержит все
нужные поля:

```bash
uv run python -c "import json;d=json.load(open('data/google-service-account.json'));print(d['type'],d['client_email'],bool(d.get('private_key')))"
```

Должно напечатать `service_account`, адрес робота и `True`. Ошибка разбора JSON
или пустой `private_key` — файл повреждён при копировании (частая история, если
содержимое вставляли через буфер обмена, а не копировали файл целиком).

Если ключ был отозван или удалён в консоли — выпустите новый (шаг 1.4) и замените
файл. Старый после этого не заработает. Содержимое файла читается один раз за
запуск, поэтому после замены **перезапустите бота** — иначе он продолжит
подписываться старым ключом.

Ещё 401 бывает, если на сервере сильно сбиты часы: подпись живёт час, и время в
ней проверяется. `timedatectl` покажет, синхронизировано ли время.

### События появились, но не в том часовом поясе

Бот отправляет каждое событие с часовым поясом его хакатона, а Google показывает
их в поясе смотрящего — это нормально. Если пояс хакатона задан неверно, чините
его в боте, а не в календаре: следующая сверка перезапишет событие.

### Удалил событие в Google, оно вернулось

Так и задумано. Источник правды — бот. Удаляйте этап в боте, и следующая сверка
уберёт его из календаря.
